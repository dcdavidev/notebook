_Pro level_

ABAP SQL and CDS cover most database logic, but SAP HANA has more to offer: **SQLScript**, its own procedural language, with variables, intermediate tables, loops, and HANA-only functions. An **ABAP Managed Database Procedure** (AMDP) lets you write SQLScript inside a method of an ABAP class. The ABAP system creates and updates the database procedure for you, and you transport it like any other ABAP code.

AMDP is the last step of the [code pushdown](./0131-code-pushdown.en.md) toolbox: use it only when ABAP SQL and CDS can't do the job.

> [!TIP]
> An AMDP is like writing a note in the local language and handing it to the chef: the waiter (ABAP) still takes the order and brings the plate, but the instructions inside the note are for the kitchen only, and only that kitchen understands them.

## An AMDP class

An AMDP class implements the marker interface `IF_AMDP_MARKER_HDB`, and its AMDP methods are implemented with `BY DATABASE PROCEDURE`:

```abap
CLASS zcl_flight_amdp DEFINITION PUBLIC FINAL CREATE PUBLIC.
  PUBLIC SECTION.
    INTERFACES if_amdp_marker_hdb.

    TYPES: BEGIN OF ty_load,
             carrid    TYPE s_carr_id,
             flights   TYPE int8,
             occupied  TYPE int8,
             occupancy TYPE decfloat34,
           END OF ty_load,
           tt_load TYPE STANDARD TABLE OF ty_load WITH EMPTY KEY.

    METHODS get_load
      IMPORTING VALUE(iv_from) TYPE s_date
      EXPORTING VALUE(et_load) TYPE tt_load.
ENDCLASS.

CLASS zcl_flight_amdp IMPLEMENTATION.
  METHOD get_load BY DATABASE PROCEDURE FOR HDB LANGUAGE SQLSCRIPT
                  OPTIONS READ-ONLY
                  USING sflight.
    -- step 1: flights of the current client from the given date
    lt_flights = SELECT carrid, seatsmax, seatsocc
                   FROM sflight
                  WHERE mandt  = SESSION_CONTEXT('CLIENT')
                    AND fldate >= :iv_from;

    -- step 2: aggregate the intermediate table
    et_load = SELECT carrid,
                     COUNT(*)      AS flights,
                     SUM(seatsocc) AS occupied,
                     ROUND(SUM(seatsocc) * 100.0 / NULLIF(SUM(seatsmax), 0), 2) AS occupancy
                FROM :lt_flights
               GROUP BY carrid
               ORDER BY carrid;
  ENDMETHOD.
ENDCLASS.
```

What to notice:

- `BY DATABASE PROCEDURE FOR HDB LANGUAGE SQLSCRIPT` makes the method body SQLScript. Comments are `--`, not `"`, and statements end with a semicolon.
- `USING` lists every table, view, and other AMDP the method reads. Anything not listed is unknown to the procedure.
- `OPTIONS READ-ONLY` promises that the method doesn't change data.
- Parameters are passed **by value**, typed with elementary types or table types with elementary columns. Inside SQLScript you read them with a colon: `:iv_from`, `:lt_flights`.
- `lt_flights` is a **table variable**: an intermediate result that HANA can optimize together with the next statement.

## Client handling

> [!WARNING]
> SQLScript doesn't know about the client. A `SELECT` on `SFLIGHT` without a client condition returns the rows of **every** client. Filter `mandt` yourself, with `SESSION_CONTEXT('CLIENT')` or with an importing parameter filled with `sy-mandt`.

When an AMDP reads CDS view entities instead of tables, use `OPTIONS CDS SESSION CLIENT current` so the views apply the current client for you.

## Calling and debugging

From ABAP, an AMDP method is called like any other method:

```abap
NEW zcl_flight_amdp( )->get_load( EXPORTING iv_from = '20250101'
                                  IMPORTING et_load = DATA(lt_load) ).
cl_demo_output=>display( lt_load ).
```

The first call creates the procedure in the database; later calls run it directly. To debug, set a breakpoint inside the SQLScript body in ADT: the **AMDP debugger** stops there and shows the scalar and table variables.

AMDP runs only on SAP HANA. If your code must also run on other databases, check first with `cl_abap_dbfeatures=>use_features( )` and the feature `cl_abap_dbfeatures=>call_amdp_method`, and provide an ABAP SQL fallback.

## When AMDP is worth it

| Use AMDP for                                                                   | Stay with ABAP SQL or CDS for                |
| ------------------------------------------------------------------------------ | -------------------------------------------- |
| multi-step logic with intermediate tables                                      | joins, filters, aggregates, `CASE`           |
| HANA-specific functions (text analysis, predictive, graph, series data)        | logic that other databases must run too      |
| the implementation of a [CDS table function](./0138-cds-table-functions.en.md) | reusable data models for Fiori and analytics |

AMDP code is harder to read, test, and debug than ABAP SQL, and it bypasses [CDS access control](./0136-cds-access-control.en.md). It also bypasses the table buffer of the application server.

## Exercise

> [!IMPORTANT]
>
> 1. Create `ZCL_FLIGHT_AMDP` with the method `get_load` and run it from a report or with `if_oo_adt_classrun`.
> 2. Remove the client condition and compare the result on a system with flight data in more than one client.
> 3. Write the same query in ABAP SQL. Which version would you keep?

### Solution

```abap
SELECT FROM sflight
  FIELDS carrid,
         COUNT( * )      AS flights,
         SUM( seatsocc ) AS occupied,
         division( SUM( seatsocc ) * 100, SUM( seatsmax ), 2 ) AS occupancy
  WHERE fldate >= '20250101'
  GROUP BY carrid
  ORDER BY carrid
  INTO TABLE @DATA(lt_load_sql).
```

Without the client condition, the AMDP adds up flights from every client. Keep the ABAP SQL version: it does the same job, handles the client automatically, and runs on every database. This AMDP is only an exercise in the syntax.

> [!NOTE]
>
> - An AMDP is a class method written in SQLScript, managed and transported by the ABAP system.
> - The class implements `IF_AMDP_MARKER_HDB`; the method uses `BY DATABASE PROCEDURE FOR HDB LANGUAGE SQLSCRIPT` and lists its sources in `USING`.
> - Parameters are passed by value; read them in SQLScript with a colon.
> - Handle the client yourself, for example with `SESSION_CONTEXT('CLIENT')`.
> - Use AMDP only when ABAP SQL and CDS can't express the logic.
