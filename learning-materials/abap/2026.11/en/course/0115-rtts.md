_Intermediate level_

Usually you know the types of your data when you write the program. Generic code doesn't: a tool that exports any table to CSV must find out at runtime which columns a row has, how long they are, and what their labels are. The **runtime type services (RTTS)** are a set of classes that give you this information (**RTTI**, runtime type identification) and let you build new types on the fly (**RTTC**, runtime type creation).

## The class hierarchy

Every type is described by an object of a subclass of `CL_ABAP_TYPEDESCR`:

```text
CL_ABAP_TYPEDESCR
├── CL_ABAP_DATADESCR
│   ├── CL_ABAP_ELEMDESCR      elementary types (c, n, i, p, d, string ...)
│   ├── CL_ABAP_REFDESCR       data references (REF TO ...)
│   └── CL_ABAP_COMPLEXDESCR
│       ├── CL_ABAP_STRUCTDESCR  structures
│       └── CL_ABAP_TABLEDESCR   internal tables
└── CL_ABAP_OBJECTDESCR
    ├── CL_ABAP_CLASSDESCR     classes
    └── CL_ABAP_INTFDESCR      interfaces
```

You get a descriptor with one of the static methods of `CL_ABAP_TYPEDESCR`:

| Method                   | Describes                             |
| ------------------------ | ------------------------------------- |
| `describe_by_data`       | the type of a data object             |
| `describe_by_name`       | a type by name (Dictionary or global) |
| `describe_by_data_ref`   | the object a data reference points to |
| `describe_by_object_ref` | the class of an object                |

The result has the static type `CL_ABAP_TYPEDESCR`, so you cast it to the subclass you expect.

> [!TIP]
> RTTI is like the label sewn inside a jacket: you don't know the size by looking at it, but the label tells you the size, the fabric, and the washing instructions. RTTC is the tailor who makes a new jacket from the measures you give.

## Describe a structure

```abap
DATA ls_flight TYPE sflight.

DATA(lo_struct) = CAST cl_abap_structdescr(
                    cl_abap_typedescr=>describe_by_data( ls_flight ) ).

WRITE: / 'Absolute name:', lo_struct->absolute_name.    " \TYPE=SFLIGHT
LOOP AT lo_struct->components INTO DATA(ls_comp).
  WRITE: / ls_comp-name, ls_comp-type_kind, ls_comp-length, ls_comp-decimals.
ENDLOOP.
```

- `components` lists name, type kind, length, and decimals of each component. The length is in **bytes**: a `c` field of 3 characters has length 6 in a Unicode system.
- `type_kind` is a one-letter code, with constants in `CL_ABAP_TYPEDESCR` such as `typekind_char` (`C`), `typekind_num` (`N`), `typekind_packed` (`P`), `typekind_date` (`D`), `typekind_string` (`g`).
- `kind` tells you the general kind: `kind_elem`, `kind_struct`, `kind_table`, `kind_ref`, `kind_class`, `kind_intf`.
- `get_components( )` returns the components with a reference to their type descriptor. It keeps an included structure as a single entry; `get_included_view( )` flattens it.

For Dictionary types you also get the field labels:

```abap
DATA(lt_fields) = lo_struct->get_ddic_field_list( p_langu = sy-langu ).
LOOP AT lt_fields INTO DATA(ls_field).
  WRITE: / ls_field-fieldname, ls_field-scrtext_m.   " medium field label
ENDLOOP.
```

## Describe by name and by reference

`describe_by_name` raises the classic exception `type_not_found` if the name doesn't exist, so use the long call form:

```abap
DATA lo_type TYPE REF TO cl_abap_typedescr.

cl_abap_typedescr=>describe_by_name(
  EXPORTING  p_name         = 'SCARR'
  RECEIVING  p_descr_ref    = lo_type
  EXCEPTIONS type_not_found = 1 ).
IF sy-subrc <> 0.
  WRITE / 'Type not found'.
ELSEIF lo_type->kind = cl_abap_typedescr=>kind_struct.
  WRITE / |SCARR is a structure with { lines( CAST cl_abap_structdescr( lo_type )->components ) } components|.
ENDIF.
```

For a table, the table descriptor gives you the line type:

```abap
DATA lt_flights TYPE STANDARD TABLE OF sflight WITH EMPTY KEY.

DATA(lo_table) = CAST cl_abap_tabledescr( cl_abap_typedescr=>describe_by_data( lt_flights ) ).
DATA(lo_line)  = CAST cl_abap_structdescr( lo_table->get_table_line_type( ) ).
```

## Create types at runtime

RTTC works the other way round: you build descriptors with the `get` methods, then create a data object of that type with `CREATE DATA ... TYPE HANDLE`. See [dynamic data objects](./0116-dynamic-data.md) for how to work with the result.

```abap
DATA(lt_components) = VALUE cl_abap_structdescr=>component_table(
  ( name = 'CARRID'    type = CAST #( cl_abap_typedescr=>describe_by_name( 'S_CARR_ID' ) ) )
  ( name = 'CARRNAME'  type = cl_abap_elemdescr=>get_c( 20 ) )
  ( name = 'FLIGHTS'   type = cl_abap_elemdescr=>get_i( ) ) ).

DATA(lo_new_struct) = cl_abap_structdescr=>get( lt_components ).
DATA(lo_new_table)  = cl_abap_tabledescr=>get( p_line_type = lo_new_struct ).

DATA lr_table TYPE REF TO data.
CREATE DATA lr_table TYPE HANDLE lo_new_table.   " a standard table of the new structure
```

`CL_ABAP_ELEMDESCR` has a `get_...` method for each elementary type: `get_c( )`, `get_n( )`, `get_p( p_length = 8 p_decimals = 2 )`, `get_string( )`, `get_d( )`, and so on.

> [!WARNING]
> `get` raises `CX_SY_STRUCT_CREATION` or `CX_SY_TABLE_CREATION` when the components are invalid (an empty or duplicate name, for example). Wrap RTTC calls in `TRY ... CATCH` when the components come from user input or configuration.

## Exercise

> [!IMPORTANT]
> Write a report with a parameter `p_type TYPE tabname DEFAULT 'SPFLI'`. If the name is a structure or a table, print each field with its type kind, length in characters, and medium field label. Otherwise print a message.

### Solution

```abap
REPORT zrtts_describe.

PARAMETERS p_type TYPE tabname DEFAULT 'SPFLI'.

START-OF-SELECTION.
  DATA lo_type TYPE REF TO cl_abap_typedescr.

  cl_abap_typedescr=>describe_by_name( EXPORTING  p_name         = p_type
                                       RECEIVING  p_descr_ref    = lo_type
                                       EXCEPTIONS type_not_found = 1 ).
  IF sy-subrc <> 0 OR lo_type->kind <> cl_abap_typedescr=>kind_struct.
    WRITE / |{ p_type } is not a structure|.
    RETURN.
  ENDIF.

  DATA(lo_struct) = CAST cl_abap_structdescr( lo_type ).
  LOOP AT lo_struct->get_ddic_field_list( ) INTO DATA(ls_field).
    WRITE: / ls_field-fieldname, ls_field-inttype, ls_field-leng, ls_field-scrtext_m.
  ENDLOOP.
```

The Dictionary field list already gives the length in characters (`LENG`), unlike `components`, which gives it in bytes.

> [!NOTE]
>
> - RTTI describes types at runtime; RTTC creates them.
> - Start from `CL_ABAP_TYPEDESCR=>describe_by_data` or `describe_by_name`, then cast to the subclass you expect.
> - `CL_ABAP_STRUCTDESCR` gives components; `get_ddic_field_list( )` gives Dictionary labels.
> - Lengths in `components` are in bytes, not characters.
> - Build new types with `CL_ABAP_STRUCTDESCR=>get` and `CL_ABAP_TABLEDESCR=>get`, then use `CREATE DATA ... TYPE HANDLE`.
