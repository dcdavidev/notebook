Di solito conosci i tipi dei tuoi dati quando scrivi il programma. Il codice generico no: uno strumento che esporta qualsiasi tabella in CSV deve scoprire a runtime quali colonne ha una riga, quanto sono lunghe e quali sono le loro etichette. I **runtime type services (RTTS)** sono un insieme di classi che ti danno queste informazioni (**RTTI**, runtime type identification) e ti permettono di costruire nuovi tipi al volo (**RTTC**, runtime type creation).

## La gerarchia delle classi

Ogni tipo è descritto da un oggetto di una sottoclasse di `CL_ABAP_TYPEDESCR`:

```text
CL_ABAP_TYPEDESCR
├── CL_ABAP_DATADESCR
│   ├── CL_ABAP_ELEMDESCR      tipi elementari (c, n, i, p, d, string ...)
│   ├── CL_ABAP_REFDESCR       riferimenti ai dati (REF TO ...)
│   └── CL_ABAP_COMPLEXDESCR
│       ├── CL_ABAP_STRUCTDESCR  strutture
│       └── CL_ABAP_TABLEDESCR   tabelle interne
└── CL_ABAP_OBJECTDESCR
    ├── CL_ABAP_CLASSDESCR     classi
    └── CL_ABAP_INTFDESCR      interfacce
```

Ottieni un descrittore con uno dei metodi statici di `CL_ABAP_TYPEDESCR`:

| Metodo                   | Descrive                                     |
| ------------------------ | -------------------------------------------- |
| `describe_by_data`       | il tipo di un oggetto dati                   |
| `describe_by_name`       | un tipo per nome (del Dizionario o globale)  |
| `describe_by_data_ref`   | l'oggetto a cui punta un riferimento ai dati |
| `describe_by_object_ref` | la classe di un oggetto                      |

Il risultato ha il tipo statico `CL_ABAP_TYPEDESCR`, quindi fai un cast alla sottoclasse che ti aspetti.

> [!TIP]
> La RTTI è come l'etichetta cucita dentro una giacca: guardandola non capisci la taglia, ma l'etichetta ti dice taglia, tessuto e istruzioni di lavaggio. La RTTC è il sarto che cuce una giacca nuova con le misure che gli dai.

## Descrivere una struttura

```abap
DATA ls_flight TYPE sflight.

DATA(lo_struct) = CAST cl_abap_structdescr(
                    cl_abap_typedescr=>describe_by_data( ls_flight ) ).

WRITE: / 'Nome assoluto:', lo_struct->absolute_name.    " \TYPE=SFLIGHT
LOOP AT lo_struct->components INTO DATA(ls_comp).
  WRITE: / ls_comp-name, ls_comp-type_kind, ls_comp-length, ls_comp-decimals.
ENDLOOP.
```

- `components` elenca nome, tipo, lunghezza e decimali di ogni componente. La lunghezza è in **byte**: un campo `c` di 3 caratteri ha lunghezza 6 in un sistema Unicode.
- `type_kind` è un codice di una lettera, con costanti in `CL_ABAP_TYPEDESCR` come `typekind_char` (`C`), `typekind_num` (`N`), `typekind_packed` (`P`), `typekind_date` (`D`), `typekind_string` (`g`).
- `kind` ti dice la categoria generale: `kind_elem`, `kind_struct`, `kind_table`, `kind_ref`, `kind_class`, `kind_intf`.
- `get_components( )` restituisce i componenti con un riferimento al loro descrittore di tipo. Una struttura inclusa resta una sola voce; `get_included_view( )` la espande.

Per i tipi del Dizionario ottieni anche le etichette dei campi:

```abap
DATA(lt_fields) = lo_struct->get_ddic_field_list( p_langu = sy-langu ).
LOOP AT lt_fields INTO DATA(ls_field).
  WRITE: / ls_field-fieldname, ls_field-scrtext_m.   " etichetta media
ENDLOOP.
```

## Descrivere per nome e per riferimento

`describe_by_name` solleva l'eccezione classica `type_not_found` se il nome non esiste, quindi usa la forma lunga della chiamata:

```abap
DATA lo_type TYPE REF TO cl_abap_typedescr.

cl_abap_typedescr=>describe_by_name(
  EXPORTING  p_name         = 'SCARR'
  RECEIVING  p_descr_ref    = lo_type
  EXCEPTIONS type_not_found = 1 ).
IF sy-subrc <> 0.
  WRITE / 'Tipo non trovato'.
ELSEIF lo_type->kind = cl_abap_typedescr=>kind_struct.
  WRITE / |SCARR è una struttura con { lines( CAST cl_abap_structdescr( lo_type )->components ) } componenti|.
ENDIF.
```

Per una tabella, il descrittore di tabella ti dà il tipo di riga:

```abap
DATA lt_flights TYPE STANDARD TABLE OF sflight WITH EMPTY KEY.

DATA(lo_table) = CAST cl_abap_tabledescr( cl_abap_typedescr=>describe_by_data( lt_flights ) ).
DATA(lo_line)  = CAST cl_abap_structdescr( lo_table->get_table_line_type( ) ).
```

## Creare tipi a runtime

La RTTC lavora al contrario: costruisci i descrittori con i metodi `get`, poi crei un oggetto dati di quel tipo con `CREATE DATA ... TYPE HANDLE`. Vedi [gli oggetti dati dinamici](./0116-dynamic-data.md) per lavorare con il risultato.

```abap
DATA(lt_components) = VALUE cl_abap_structdescr=>component_table(
  ( name = 'CARRID'    type = CAST #( cl_abap_typedescr=>describe_by_name( 'S_CARR_ID' ) ) )
  ( name = 'CARRNAME'  type = cl_abap_elemdescr=>get_c( 20 ) )
  ( name = 'FLIGHTS'   type = cl_abap_elemdescr=>get_i( ) ) ).

DATA(lo_new_struct) = cl_abap_structdescr=>get( lt_components ).
DATA(lo_new_table)  = cl_abap_tabledescr=>get( p_line_type = lo_new_struct ).

DATA lr_table TYPE REF TO data.
CREATE DATA lr_table TYPE HANDLE lo_new_table.   " tabella standard della nuova struttura
```

`CL_ABAP_ELEMDESCR` ha un metodo `get_...` per ogni tipo elementare: `get_c( )`, `get_n( )`, `get_p( p_length = 8 p_decimals = 2 )`, `get_string( )`, `get_d( )` e così via.

> [!WARNING]
> `get` solleva `CX_SY_STRUCT_CREATION` o `CX_SY_TABLE_CREATION` quando i componenti non sono validi (per esempio un nome vuoto o duplicato). Racchiudi le chiamate RTTC in un `TRY ... CATCH` quando i componenti arrivano da un input dell'utente o da una configurazione.

## Esercizio

> [!IMPORTANT]
> Scrivi un report con un parametro `p_type TYPE tabname DEFAULT 'SPFLI'`. Se il nome è una struttura o una tabella, stampa ogni campo con il suo tipo, la lunghezza in caratteri e l'etichetta media. Altrimenti stampa un messaggio.

### Soluzione

```abap
REPORT zrtts_describe.

PARAMETERS p_type TYPE tabname DEFAULT 'SPFLI'.

START-OF-SELECTION.
  DATA lo_type TYPE REF TO cl_abap_typedescr.

  cl_abap_typedescr=>describe_by_name( EXPORTING  p_name         = p_type
                                       RECEIVING  p_descr_ref    = lo_type
                                       EXCEPTIONS type_not_found = 1 ).
  IF sy-subrc <> 0 OR lo_type->kind <> cl_abap_typedescr=>kind_struct.
    WRITE / |{ p_type } non è una struttura|.
    RETURN.
  ENDIF.

  DATA(lo_struct) = CAST cl_abap_structdescr( lo_type ).
  LOOP AT lo_struct->get_ddic_field_list( ) INTO DATA(ls_field).
    WRITE: / ls_field-fieldname, ls_field-inttype, ls_field-leng, ls_field-scrtext_m.
  ENDLOOP.
```

L'elenco dei campi del Dizionario dà già la lunghezza in caratteri (`LENG`), a differenza di `components`, che la dà in byte.

> [!NOTE]
>
> - La RTTI descrive i tipi a runtime; la RTTC li crea.
> - Parti da `CL_ABAP_TYPEDESCR=>describe_by_data` o `describe_by_name`, poi fai il cast alla sottoclasse che ti aspetti.
> - `CL_ABAP_STRUCTDESCR` ti dà i componenti; `get_ddic_field_list( )` le etichette del Dizionario.
> - Le lunghezze in `components` sono in byte, non in caratteri.
> - Costruisci nuovi tipi con `CL_ABAP_STRUCTDESCR=>get` e `CL_ABAP_TABLEDESCR=>get`, poi usa `CREATE DATA ... TYPE HANDLE`.
